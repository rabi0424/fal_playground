# サイドバー UI 設計書

上部に横並びだった画面切替を、左の開閉式サイドバーへ集約したときの決定事項。
`docs/mobile-ui-design.md`（スマホ対応）と同じく、実装より前に「どうするか」を決めたもの。

## 1. 何が問題だったか

機能は 5 画面（生成 / 画像編集 / 部分AI編集 / 比較アリーナ / LoRA ライブラリ）あるのに、
移動手段はトップバーの横並びボタンだけだった。

1. **増えるほど狭くなる。** 横並びは幅を食い合う。実際 430px 以下ではバー内を
   横スクロールさせて逃がしており、右端の項目は「あることに気づけない」状態だった。
2. **LoRA ライブラリだけ入口が違う。** バーに入りきらず、生成フォームの LoRA
   アコーディオンの中にリンクが埋まっていた。
3. **同じものを 5 回書いていた。** 各 HTML がトップバーを手書きし、テーマ切替の
   JS も 5 ファイルに丸ごと重複。文言や `title` が画面ごとに少しずつズレていた。
4. **現在地が弱い。** ブランドの右に「/ 画像編集」と継ぎ足す表示だけで、
   どの画面にいるかは読まないと分からなかった。

縦に並べれば項目の増減に強く、現在地は行のハイライトで一目で分かる。

## 2. 決定

### 2.1 構造

全画面共通のシェルを 1 つ持つ。HTML 側が用意するのは器だけで、中身は `shell.js`
が描画する（同じマークアップを 5 回書かないため）。

```
<div class="shell">
  <aside id="appSidebar" class="sidebar"></aside>   ← shell.js が描画
  <div class="shell-body">
    <header class="pagebar">…</header>              ← shell.js が挿入
    <main>… 各画面 …</main>
  </div>
</div>
```

`shell.js` が持つのは、ナビゲーション・現在地の判定・開閉状態・テーマ・
ドロワーの開閉（スワイプ / Esc / フォーカス）まで。各画面の JS からテーマ関連は
すべて削除した。

### 2.2 3 つの状態

| 状態 | 幅 | 条件 |
|---|---|---|
| 展開 | 240px | 901px 以上の既定 |
| レール | 64px | 畳んだとき。アイコンのみ・`title` でツールチップ |
| ドロワー | min(272px, 85vw) | 900px 以下。スクリムの上に重なる |

- 展開 / レールの選択は `localStorage`（`fal_sidebar`）に保存し、画面をまたいでも保つ。
- 畳むときに動かすのは**幅だけ**。中身の位置まで動かすと視線が散る。
- 900px 以下ではレールにはしない。指で 64px の列を使うより、必要なときだけ
  引き出すほうが確実で、本文に使える幅も広い。

### 2.3 項目

```
fal playground                    [畳む]
─────────────────────────────────
  ✦  生成                ← index.html
  ✎  画像編集            ← imgedit.html
  ⌗  部分AI編集          ← edit.html
  ▯▯ 比較アリーナ         ← arena.html
  ≋  LoRA ライブラリ      ← library.html
─────────────────────────────────
  ▁▃ 統計
  [ 自動 | ライト | ダーク ]
```

- **LoRA ライブラリを昇格。** フォームの中のリンクではなく、他と同格の画面として置く
  （生成フォーム側のリンクは動線として残す）。
- **統計**は履歴データを持つ生成画面のダイアログなので、他画面からは `./#stats`
  へ遷移して開く。開いたらハッシュは消す（再読み込みで開き直さないため）。
- **テーマは 3 択に変更。** 以前は押すたび 自動 → ライト → ダーク と巡回するボタンで、
  今どれを選んでいるかは文言を読むまで分からなかった。3 つ並べて選択中を面で示す。
  レールでは縦積みにする。

### 2.4 ページバー

サイドバーが現在地を示すので、上部に残すのは画面名の見出しだけ。

- 901px 以上: 本文と同じ最大幅・同じ左端に揃えた `<h1>`。固定しない。
- 900px 以下: 上端に貼り付く半透明バー。左にハンバーガー。実高さ（Dynamic Island
  ぶんを含む）を `--shell-top` として公開し、その下に貼り付く要素（LoRA ライブラリの
  検索バー）が使う。

### 2.5 操作

| 操作 | 動作 |
|---|---|
| ⌘/Ctrl + B | 開閉。入力欄・テキストエリア・contenteditable にフォーカスがあるときは横取りしない |
| 左端からの払い | ドロワーを開く（900px 以下）。右端はブラウザの「進む」と衝突するので使わない |
| 左向きの払い / Esc / スクリムのタップ | ドロワーを閉じる |
| ドロワー内の移動 | 閉じてから遷移する（戻ったときに開いたままにしない） |

ドロワーを開いている間は、背後をスクロールさせず、フォーカスも外へ出さない。
下部固定の生成バー（`z-index: 50`）より前に出す。

## 3. 併せて直した細部

1. **テーマのちらつき。** `data-theme="auto"` で描画してから JS で当てていたため、
   OS がライトで保存値がダークだと初期表示が一瞬白かった。`<head>` のインライン
   スクリプトで、描画前にテーマとサイドバーの開閉を反映する。
2. **形のトークン化。** 角丸を `--radius-panel: 12px`（面）と `--radius-control: 8px`
   （面の中の部品）の 2 段階だけにし、共有部品はこれを参照する。
3. **サイドバーの面。** 本文よりわずかに沈んだ `--sidebar-bg` を置き、操作の層と
   内容の層を分ける（HIG の Materials / Layout: 操作とコンテンツを同じ平面に置かない）。
4. **アイコン。** 文字（`⬆` `✕` など）ではなく、`currentColor` の 20px ストローク SVG に
   統一する。まずはサイドバーとページバーから。
5. **アクセシビリティ。** 現在地に `aria-current="page"`、開閉に `aria-expanded`、
   テーマに `aria-pressed`、リンクにも `:focus-visible` のリング。
   `prefers-reduced-transparency` ではページバーとスクリムのぼかしをやめる。
   `prefers-contrast: more` ではサイドバーの境界もはっきりした線に戻す。
